## Stored fields / runtime & browser required integration

`CustomAgentDefinition` adds `pluginSelection?: AgentPluginSelection`, `revision:number`, `pluginMigration?: AgentPluginMigrationReport`. Undefined selection means **unmigrated legacy**, never defaults/empty-success. New v2 agents always have an explicit selection. `skills`, `contextFiles`, `subagents` remain independent user/manual resources. Legacy nativeTools/mcpServers/piPackages/runControl/goalControl are read-only migration input; regular v2 writes reject them. Runtime must not execute legacy fields when pluginSelection is present; unknown/unmigrated rows must be diagnosed, not silently activated.

`CustomAgentStore.update(id,input,{expectedRevision})` performs SQL CAS; plugin-schema agents require expectedRevision. Create/preview/update validate core selection shape. Profile/Bootstrap/UI serializers must preserve pluginSelection, revision, pluginMigration. Browser-owned `types.ts` should add those fields (SDK type imports); no alternate selection DTO. Store exports `profileConsumerCollector(agentStore)` -> `(pluginId)=>Promise<PluginConsumer[]>`, includes archived agents and unknown legacy dependencies. Orchestrator combines it with builtin-profile/runtime consumers.

## Migration / AP12–14 dependency

Migration is parameterized by **actual installed manifests and a baseline effective selection inventory**; no competing hardcoded capability list. It matches legacy names against contribution `kind`/`name`, honors required/dependencies through core resolver and compares exact before/after contribution identities and tool names. Builtin extraction owner must preserve old contribution names and publish authoritative family mapping. Fixtures use actual legacy-builtin-catalog.json, Goal default and minimal yielded-run/subagent infrastructure inventory. Unknown Pi packages are retained in backup/report, never loaded.

AgentStore migration stage uses Management `PluginMigrationJournal` and its own atomic CAS + source hash marker, not a fake cross-DB transaction. Raw row export is backed up before mutation; isApplied verifies own store marker after crash before journal checkpoint. Dry-run produces exact before/after sets and conflicts without writes.
